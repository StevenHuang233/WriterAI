# WriterAI 小说提词器

本地运行的网页写作应用：停笔片刻，AI 结合**上下文、设定库与前情摘要**，在光标处给出灰色提示，按 `Tab` 接受。

## 功能

- **停顿提词**：默认停止输入 4 秒后触发（可调 2–10 秒）；中文输入法组词时不触发；每次停顿只请求一次；连续忽略会自动拉长间隔
- **接受方式**：`Tab` 全部接受 · `Cmd/Ctrl + →` 接受到下一个标点 · `Esc` 忽略 · `Cmd/Ctrl + J` 手动提词 · `Cmd/Ctrl + Shift + J` 续写一段
- **设定库（Lorebook）**：人物 / 地点 / 物品 / 势力 / 世界观，支持别名；正文中出现名称或别名时自动带入上下文（关键词触发），可设常驻与优先级
- **历史压缩**：章节摘要 → 全书梗概（滚动合并）→ 人物当前状态自动更新；手改摘要自动锁定
- **双模型**：快速模型负责实时提词，强模型负责摘要与续写（可分别配置，例如快速用 DeepSeek / 本地 Ollama 小模型，强模型用大模型）
- 导出 txt / markdown，深色主题，数据存本地 SQLite

## 快速开始

要求 Node.js ≥ 20.19（建议 22）。

```bash
npm install
cp .env.example .env   # 填入模型配置
npm run dev            # 打开 http://localhost:5173
```

生产模式（单端口）：

```bash
npm run build
npm start              # http://127.0.0.1:8787
```

## 模型配置（.env）

| 变量 | 说明 |
|---|---|
| `FAST_BASE_URL` / `FAST_API_KEY` / `FAST_MODEL` | 快速模型：实时提词（OpenAI 兼容接口） |
| `STRONG_BASE_URL` / `STRONG_API_KEY` / `STRONG_MODEL` | 强模型：摘要 / 梗概 / 人物状态 / 续写 |

兼容 DeepSeek、通义千问、Kimi、OpenAI 以及本地 Ollama / LM Studio（示例见 `.env.example`）。密钥只保存在 `.env`，不会发送到前端。

## 使用建议

1. 建项目后先在右侧「风格」页写**故事简介**与**风格指令**
2. 在「设定」页添加主要人物（名称、别名、设定、常驻开关）
3. 开始写作。前几章写完后，「前情」页会出现自动摘要；越往后，提词越"记得"前面的剧情
4. 状态栏可看到本次提词用到了哪些设定

## 前情分层压缩 + 上下文链条

章节多了之后，越老的章节被压得越狠。现在采用**近详远略 + 远段合段**的分层压缩，让**全书都有机会留在上下文里**：

| 距当前章 | 压缩方式 | 每条上限 |
|---|---|---|
| 1～2 章 | 完整摘要（一章一条） | 320 字 |
| 3～8 章 | 一句话摘要（一章一条） | 90 字 |
| 9～22 章 | **每 3 章压成一段** | 130 字/段 |
| 23～45 章 | 每两个章段合一条 | 90 字 |
| 45 章以外 | 每三个章段合一条 | 60 字 |

- **远段合段压缩**：远处章节不再逐章罗列（那样会被单章上限切碎），而是把连续几章交给强模型压成一段连贯的话，保留因果链与伏笔；合段粒度（每几章一段）可在「上下文」页调整，也可手动「重新压缩远段」
- 合段摘要在后台随章节摘要自动生成并缓存（源摘要没变就不重复调用模型）；还没生成时，先用各章极简摘要拼接兜底
- 生成章节摘要时一次产出**三个层级**（完整 / 一句话 / 极简），按需取用
- 预算用满时，**优先保留近处章节**；远的先被挤掉
- 实测：12 章时前情 11 章全部纳入共 9 条；第 1–3 章压成 74 字的一段连贯前情

右侧新增 **「上下文」** 标签页，可以看到并手动调整：

- **结构图**（默认视图）：叶子是每章摘要，往上是 3 章 / 6 章 / 12 章一段的多章压缩。
  颜色表示这次提词**实际用到**哪些节点：绿色已纳入、蓝色已锁定、橙色被预算挤掉、
  紫色已固定、红色已排除、灰色未使用。默认展开所有用到的节点及其祖先
  - 每个节点可「**用此层**」：手动指定用这个粒度进入上下文（比如你想让第 4–6 章
    作为一个整体回顾，而不是被自动合成更大的段）
  - 也可「排除」/「固定」；排除和固定对该节点覆盖的所有章节生效
- 每个上下文块的字数，可**开关**（不想带的块关掉即可省上下文）
- 前情链条按顺序列出（近处一章一条，远处一段一条）：**档位、字数、是否纳入、未纳入原因**；合段条目会标注「模型压缩」或「摘要拼接」
- 每章（或每个合段）可**排除**或**固定**（固定的章节始终以完整摘要进入，优先占位）

设置保存在项目里（`project_context_settings`），换章节会自动按距离重新计算。

## 其他功能

- **写作统计**：今日字数、连续写作天数、近 14 天柱状图、各章字数
- **全文搜索 / 批量替换**：跨全部章节搜索，点击结果跳转并选中；可一键全部替换（**替换前自动存版本**，可在「历史」回退）
- **本地版本历史**：写满 500 字或每 5 分钟自动留版本（最多 30 个），也可手动保存；可恢复任意版本（恢复前会先保存当前内容）
- **章节大纲**：每章可写细纲，提词时带上本章大纲，让 AI 朝你设定的方向推进
- **导入稿件**：粘贴 Markdown 或纯文本，按 `# 标题` / `第X章` / 整篇一章 三种方式拆分为章节

## 模型配置（可在界面里改）

设置 → **模型** 里可以直接配置两个模型，不用改文件、不用重启：

- **快速模型**（实时提词）和**强模型**（摘要 / 梗概 / 人物状态 / 续写）分别配置
- 预设一键填入：DeepSeek、智谱 GLM、通义千问、Kimi、本地 Ollama
- **「获取可用模型」** 会拉取该服务支持的模型列表供选择
- **「测试连接」** 实际调一次模型，返回耗时
- 可设置**思考力度**（推理模型建议 low）
- 保存后立即生效；点「用 .env」可恢复为配置文件中的值

配置存在 `data/llm-config.json`（仅本人可读），**优先级高于 `.env`**。密钥在接口返回中是打码的。
`.env` 仍是初始配置方式（`FAST_*` / `STRONG_*`）。

## 桌面版（Electron）

有自己的窗口、Dock 图标，不依赖浏览器标签页：

```bash
npm run app          # 构建并启动桌面版
```

- 应用会在后台用系统 Node 启动后端（依赖 `server/dist`，所以会先构建）
- 数据仍然是本地的 `.env`、`data/`，和网页版完全共用
- 打包成可分发的 dmg / zip：`cd app && npm run dmg`（需先 `npm install`，会下载 electron-builder）

> 说明：后端用了原生模块（better-sqlite3），直接用 Electron 内置 Node 运行会有 ABI 不匹配，
> 因此桌面版用系统已安装的 Node 跑后端，Electron 只负责窗口。

## 云端存储（可自由选择服务商）

本地数据会打包成一个快照文件（`writerai-sync.json`，含全部项目、章节、设定、摘要），推送到你选的云端；也能随时拉回来。

支持四种，在「设置 → 云同步」里切换：

| 类型 | 适用 | 需要填什么 |
|---|---|---|
| **本地文件夹** | Dropbox / iCloud / OneDrive / 坚果云的**本地同步目录**，或任意备份文件夹 | 目录路径 |
| **S3 兼容** | AWS S3、Cloudflare R2、阿里云 OSS、腾讯云 COS、自建 MinIO | Endpoint、Region、Bucket、Access Key、Secret |
| **WebDAV** | 坚果云、Nextcloud、ownCloud | 地址、用户名、密码（建议用应用密码） |
| **GitHub Gist** | 存为私有 Gist，**自带版本历史** | Token（需 gist 权限），Gist ID 留空则自动创建 |

- **立即备份 / 从云端恢复（合并）/ 以云端为准（覆盖本地）** 三种操作
  - 合并：按 id 覆盖，本地独有的项目保留
  - 覆盖：先清空本地，完全以云端为准（会二次确认）
- **自动备份**：可开启，本地有改动后按间隔（默认 10 分钟）自动上传
- 密钥保存在 `data/sync-config.json`（权限 600），**不会返回给浏览器**（界面上显示为 `••••••`）
- 从云端下载的数据会先做结构校验再导入

## 架构

- `server/`：Hono + SQLite（better-sqlite3）。`src/context/` 是上下文组装器（预算裁剪 + 关键词触发），`src/jobs/` 是后台摘要队列
- `web/`：Vite + React + TipTap。`src/editor/` 是空闲触发器、幽灵文本扩展与后处理
- 详细设计见 [docs/DESIGN.md](docs/DESIGN.md)

```bash
npm test        # vitest：上下文组装、关键词触发、预算裁剪、空闲触发器、后处理
npm run typecheck
```
